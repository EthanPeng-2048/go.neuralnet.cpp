## 回放性能

固定 19×19、200 手、无磁盘 I/O。测试预热后统计 15 次：

| 指标 | 结果 |
|---|---:|
| 中位数 | **0.600 ms/局** |
| 独立公开样本 | **0.645 ms/局** |
| DoD | `<5 ms/局` |

这里测量的是 `Game` 创建后 200 手合法走子及 KataGo 历史维护；不包含 SGF 文件读取、
Python 进程启动或 subprocess IPC。因此它是规则内核指标，不是 CLI 端到端延迟。

## 命令

```bash
cmake --preset cpu
cmake --build --preset cpu
ctest --preset cpu --output-on-failure
```

本地结果：CTest **4/4**。系统安装 `gnugo` 后，CMake 会额外注册
`go_rules_m1_gnugo_crosscheck`；本次用临时解包的 GNU Go 3.8 单独执行并通过。

额外用 ASan + UBSan 构建运行规则题库，启用 `GO_SKIP_PERF_ASSERT=1` 跳过被插桩
放大后的性能阈值；未发现内存或未定义行为错误。

## 解释边界

- 规则语义来自 KataGo，不代表本项目已通过 KataGo 全量测试集；本项目题库只验证
  被项目直接依赖的路径。
- GnuGo 对拍覆盖提子与自杀，不覆盖全部劫型、终局和特殊规则配置。
- 5 ms 门槛是单机 CPU Release 指标；后续 MCTS 的规则节点创建仍需单独测量。
