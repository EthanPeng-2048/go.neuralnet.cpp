## 1. 核心思想

把搜索**摊进序列**：不让树在外部生长，而是让网络用 token 逐手"念出"推演线，
每念一手用一次增量前向（KV cache）。线性读棋，token 记账。

- 每个思考 ply 只花 **30 MFLOP**（2×15M，KV cache 保住历史）+ 重读权重
  ≈ 0.15–0.3ms；而 MCTS 每个叶子要**整段上下文重跑**（2–3 GFLOP）。
  这是思考路线相对搜索的唯一结构性优势（01 §2 的修正结论）。
- 代价：串行（无法跨局批量）、节点无价值回传、盘面在想象中推导且**无外部校验**。

## 2. 架构（decoder-only + 盘面前缀）

```
上下文（causal，CausalSelfAttention/GPTBlock 先例，自写 forward_step KV cache）：
  [盘面区域 token ×25（方案 1 §3.1 同款 conv stem，作为前缀）
   | 历史 move token ×K=64 | 思考链 tokens（0..B）| <MOVE> ]
                        ↓
          TransformerDecoderBlock ×N（复用 d_model/d_ff/层数规格）
                        ↓
   思考阶段：逐 token 解码（logits → 词表全集）
   决策阶段：<MOVE> 之后的 logits 只取 362 个坐标 token
```

- **盘面推导机制**：没有新盘面输入。网络必须从"真实盘面（前缀）+ 想象走子
  token 序列"经注意力重新推导当前想象局面——可学，但组合深度受网络深度限制
  （12 层对 30 手组合的表达能力未知），且错了没有机制发现（01 §4）。
- **共享**：盘面分支、历史分支、词表、GoLoss、训练器与方案 1 共享 ~80%；
  新增 = causal block 接线 + 思考语言 + 采样循环。

## 3. 结构化思考语言（mini-grammar，**非自然语言**）

词表 = 方案 1 的 362 坐标 token + 语法 token（~10 个）：

| token | 语义 |
|---|---|
| `<THINK>` / `<MOVE>` | 段界；`<MOVE>` 后的 logits 只解码坐标 |
| `|` | 变化线分隔（一条线一个评估） |
| `@` / `!` | 本手方落子 / 对方应手（坐标紧随其后） |
| `×` | 提子声明（规则引擎可验证：`@ D4 ! C4 ×` = 声明 C4 被提） |
| `W` / `L` / `E` | 该线结论：胜 / 负 / 均势（蒸馏时由 MCTS 的 Q 值阈值化；RLVR 时可被终局校验） |

示例：`<THINK> @ D4 ! C4 × E | @ Q16 ! D16 L <MOVE> D4`

**为什么必须结构化**：可验证性。`×` 声明、`W/L/E` 结论都能被规则引擎/终局
精确核对——这是 Go 相对 LLM 的独有优势（01 §6），自然语言链拿不到中间步骤的
verifiable reward。

## 4. 训练路径（三步，及为什么排 M10）

| 步骤 | 内容 | 归属 | 前置 |
|---|---|---|---|
| Step 0 | 方案 1 监督训练（π/v） | **本库（M7）** | — |
| Step 1 | **MCTS 蒸馏 SFT**：对**人类棋局局面**跑 MCTS（用当前网），取 PV 坐标序列 + 节点 Q（阈值化为 `W/L/E`）→ 模板确定性生成思考链 → SFT。单次、无人自对局、无策略梯度 ⇒ **监督形态，属本库** | 本库（M10 前半） | M8 MCTS 推理 |
| Step 2 | **RLVR**：自对局 + GRPO/PPO；奖励 = 终局胜负 + 中间步骤验证分（规则引擎逐条重放 `×`/`W/L/E`）。**当前按 D9 移出本轮范围**；上游 v1.12.0 已提供训练原语 | Step 1 + 围棋环境/自对局应用层 | 重开 D9 范围 |

冷启动链条：方案 1 → MCTS → Step 1 蒸馏——**没有 MCTS 就没有 Step 1 的数据**，
这就是关键路径论证（01 §5）：即使方案 2 最终更强，它也排在 M8 之后。

## 5. 推理循环

1. 前缀 prefill 一次（盘面 + 历史，~90 token）；
2. 逐 token 采样思考链，**预算上限 B**（默认 512 token，可调；B=0 退化为方案 1
   的先验直出）；
3. `<MOVE>` 后解码坐标（−inf 合法性掩码，规则系统为唯一真源）；
4. 可选：**多次思考采样 + 投票**（N 条链各出一票，多数为最终手）——低成本
   多样性，等效于线级 MCTS。

## 6. 经济账（口径同 01 §2/§3，M0 校准）

| | 方案 1 + MCTS（40 visits） | 方案 2 思考（B=1000） |
|---|---|---|
| 单节点成本 | 叶子 2–3 GFLOP，批量摊薄 0.75–1.5ms | **30 MFLOP + 权重重读 ≈ 0.15–0.3ms** |
| 每手墙钟（单局对弈） | ~50–100ms（批 40 叶子） | 150–300ms（B=1000，串行） |
| 自对局/局（若做，属 RL） | ~5s（8 千评估） | ~50s（20 万 token） |
| Step 1 蒸馏数据成本 | — | 与对局同价（每局面一次 MCTS） |
| Step 2 训练/局 | 1.8 TFLOP（方案 1 口径） | 18 TFLOP（**10×**） |

## 7. 与方案 1 的关系

- **不是替代，是叠层**：方案 2 = 方案 1 的盘面/历史分支 + causal 头 + 思考语言；
  方案 1 的 ckpt 可直接热启动方案 2（盘面分支权重同构）。
- **关键路径**（01 §5）：依赖 M8（MCTS 数据）→ 赌约时间线塞不下 → M10。
- **与 D9 的交互**：Step 1（蒸馏 SFT）属本库；Step 2（自对局 RLVR）按 D9
  移出本轮。上游 v1.12.0 已提供 RL 原语，剩余前置是围棋环境、自对局与范围决定，
  不再是上游库缺口。

## 8. 风险

| 风险 | 说明 |
|---|---|
| 盘面推导深度受限 | 12 层网络组合 30 手想象局面的能力未知；深度-容量曲线只能实验测 |
| 无外部校验 | 推理时 `×`/`W/L/E` 声明错了没人抓（训练时有规则引擎，推理时没有）|
| 链分布漂移 | RLVR 后思考链可能退化为网络内部黑话（语义不可读）——不影响棋力，影响可调试性 |
| 串行吞吐 | 自对局无跨局批量（但自对局属 RL，已移出）；对弈单局无此问题 |
| 上游依赖 | v1.12.0 已解除 RL 原语阻塞；Step 2 仍受 D9 范围与应用层实现约束 |

## 9. 成功判据（M10 立项后按序验收）

1. **蒸馏有效性**：Step 1 后，纯思考（B=512，0 visits）vs 方案 1 纯先验
   （0 visits）的棋力差（Arena，vs GnuGo 固定档）；
2. **等预算比较**：思考 128 token + 20 visits vs 0 token + 40 visits——
   同推理预算下谁强（这是"思考换搜索"假设的直接检验）；
3. **步骤质量曲线**：链上 `×` 声明正确率随深度的衰减（验证 §8 第一条）；
4. 若 1 不成立 → 方案 2 作为"MCTS 压缩器"重新评估（低 visits 保险）或归档。
