# 围棋混合模型设计方案（可实施文档）

## 1. 目标与约束

### 1.1 目标

设计一个中国规则 19×19 围棋模型，满足：

1. 低推理开销：单步推理延迟可控，MCTS 模拟次数可在 64–200 量级运行。
2. 低训练开销：优先使用 KataGo 等强引擎数据做监督/蒸馏训练，不从零自对弈。
3. 高能力密度：在给定参数量和推理延迟下，保留局部战术精度与全局/历史理解能力。

### 1.2 约束

- 规则：中国规则，19×19，贴目默认 7.5，含 pass、打劫、禁全同。
- 推理：保留传统 MCTS，网络提供策略先验 \(P\) 和价值 \(V\)。
- 架构：CNN 主干 + Transformer Encoder 历史编码 + 交织融合。

---

## 2. 总体架构

```
输入
├── 当前棋盘空间特征 F_board: [B, C_in, 19, 19]
├── 历史记录 H: 最近 T 步的棋盘/落子信息
└── 全局标量特征 g: [B, G]

数据流
F_board ──► CNN 主干（N 个残差块，分阶段）
                │
                ├── 在若干融合点，CNN 空间 token 作为 Query
                │       历史 Encoder 输出作为 Key/Value
                │       执行轻量 Cross-Attention / 门控融合
                │
                ▼
        融合后的空间特征 F_fused: [B, C, 19, 19]
                │
        ┌───────┴────────┐
        ▼                ▼
   策略头 Policy     价值头 Value
   输出 362 维先验    输出胜率/盘面差
        │                │
        └───────► MCTS ◄─┘
                    │
                    ▼
                落子选择
```

核心分工：

- CNN 主干：提取局部棋形、气、断点、眼位等空间特征，生成策略先验和价值。
- Transformer Encoder：编码最近 \(T\) 步历史，输出历史上下文 token 序列。
- 融合模块：在 CNN 主干若干阶段，用交叉注意力将历史上下文注入空间特征。
- MCTS：使用网络输出的策略先验和价值估计进行树搜索。

---

## 3. 输入表示

### 3.1 当前棋盘空间特征 \(F_{board}\)

建议输入通道 \(C_{in}\) 包含以下平面，每个平面为 19×19 二值或小整数：

| 通道组 | 内容 | 通道数建议 |
|---|---|---|
| 己方棋子 | 当前局面己方棋子位置 | 1 |
| 对方棋子 | 当前局面对方棋子位置 | 1 |
| 轮到谁下 | 全 1 或全 0 平面 | 1 |
| 气 | 每块棋的气数（归一化或分段二值） | 1–3 |
| 打劫禁着点 | 当前打劫禁着点 | 1 |
| 最近 1–3 步落子 | 最近落子位置平面 | 1–3 |
| 征子可逃性 | 可选，KataGo 风格征子特征 | 0–4 |
| 活棋区域/眼位 | 可选，简单眼位或区域特征 | 0–4 |
| 边界/星位 | 可选坐标先验 | 0–2 |

默认最小配置：己方棋子、对方棋子、轮次、气、打劫禁着点、最近 3 步落子，共约 8–10 通道。其余特征按训练数据与工程成本增补。

### 3.2 历史记录 \(H\)

历史记录采用最近 \(T\) 步，默认 \(T=8\)。每一步生成一个历史 token，包含：

1. 该步落子坐标嵌入：361 个位置 + pass，共 362 类，嵌入维度 \(d_h\)。
2. 该步棋盘状态摘要，二选一：
   - 方案 A（低开销）：将该步棋盘 19×19 展平为 361 维，经线性层投影到 \(d_h\)。
   - 方案 B（更强表达）：共享微型 CNN（2 层 16 通道）编码该步棋盘为向量，再投影到 \(d_h\)。
3. 时间步嵌入：可学习的时间位置编码，区分“上一步、上上步……”。
4. 可选全局摘要：该步的提子数、pass 标记、打劫状态等标量，投影后相加。

默认采用方案 A。历史 token 序列长度 \(T=8\)，每个 token 维度 \(d_h=128\)。

### 3.3 全局标量特征 \(g\)

包括：贴目、当前手数、双方提子数、pass 次数、规则标识、奇偶性等。经 MLP 投影后，可在价值头或融合模块中作为条件注入。

---

## 4. CNN 主干

### 4.1 基本结构

- 输入：\(F_{board}\)，形状 \([B, C_{in}, 19, 19]\)。
- 初始卷积：\(3\times3\) 卷积，通道 \(C\)，默认 \(C=96\) 或 \(128\)。
- 残差块：\(N\) 个标准残差块，每个包含两个 \(3\times3\) 卷积 + BatchNorm/GroupNorm + ReLU。
- 默认 \(N=8\)，可在 6–12 之间调整。
- 通道数默认 \(C=96\)，若追求更低开销可降至 64。

### 4.2 阶段划分

将 \(N\) 个残差块划分为若干阶段，便于插入融合模块：

- Stage 1：Block 1–2
- Stage 2：Block 3–4
- Stage 3：Block 5–6
- Stage 4：Block 7–8

默认在 Stage 2 之后和 Stage 4 之前各插入一个历史融合模块。融合点数量 \(K=2\) 为默认值，可按开销预算调整为 1–3。

---

## 5. 历史 Encoder

### 5.1 结构

- 类型：Transformer Encoder。
- 层数 \(L_h\)：默认 2 层，可调 1–4。
- 注意力头数：默认 4。
- 前馈维度：默认 \(4 d_h\)。
- 隐藏维度 \(d_h\)：默认 128。
- 激活：GELU；归一化：LayerNorm；残差连接。
- 不使用因果掩码，历史 token 之间双向注意力。

### 5.2 输入

历史 token 序列 \(H_{tok} \in \mathbb{R}^{B \times T \times d_h}\)，由 3.2 节生成。加入时间位置编码后送入 Encoder。

### 5.3 输出

历史上下文 \(H_{ctx} \in \mathbb{R}^{B \times T \times d_h}\)。该输出作为融合模块的 Key/Value 来源。

### 5.4 开销控制

- \(T\) 默认 8，最大不超过 16。
- \(L_h\) 默认 2，若延迟敏感可降至 1。
- 历史 token 的棋盘摘要默认用线性投影，不用大 CNN。
- 历史 Encoder 可每步缓存？注意历史序列随对局滑动，简单实现不缓存；若需优化，可缓存单步棋盘摘要嵌入，Encoder 仍需重跑。

---

## 6. 融合模块

### 6.1 融合方式

采用交叉注意力融合。

### 6.2 交叉注意力定义

在融合点，取 CNN 当前空间特征 \(F \in \mathbb{R}^{B \times C \times 19 \times 19}\)。

1. 生成 Query：
   - 将 \(F\) 通过 \(1\times1\) 卷积投影到 \(d_h\)，得到 \(Q_{map} \in \mathbb{R}^{B \times d_h \times 19 \times 19}\)。
   - 为控制 token 数，可选下采样：按 \(2\times2\) patch 展平，得到约 \(10\times10=100\) 个空间 token；或直接使用 361 个 token。默认使用 2×2 patch 下采样，得到 \(Q \in \mathbb{R}^{B \times 100 \times d_h}\)。
2. Key/Value：来自历史 Encoder 输出 \(H_{ctx}\)，经线性投影得到 \(K,V \in \mathbb{R}^{B \times T \times d_h}\)。
3. Cross-Attention：
   \[
   \text{Attn} = \text{softmax}\left(\frac{Q K^\top}{\sqrt{d_h}}\right) V
   \]
   输出 \(A \in \mathbb{R}^{B \times 100 \times d_h}\)。
4. 回写空间特征：
   - 将 \(A\) 还原为 \(10\times10\) 的空间布局，经转置卷积或双线性上采样回 \(19\times19\)，再通过 \(1\times1\) 卷积投影回 \(C\) 通道。
   - 与原始 \(F\) 做残差相加：
     \[
     F' = F + \gamma \cdot \text{UpSample}(\text{Proj}(A))
     \]
   - \(\gamma\) 为可学习的门控标量或逐通道门控，初始化为小值（如 0.1），保证训练初期以 CNN 特征为主。

### 6.3 融合点默认配置

| 融合点 | 位置 | Query token 数 | 说明 |
|---|---|---|---|
| Fusion-1 | Stage 2 后 | 100（2×2 patch） | 中期融合，注入短期历史 |
| Fusion-2 | Stage 4 前 | 100（2×2 patch） | 后期融合，注入全局历史上下文 |

若延迟敏感，只保留 Fusion-2；若能力不足，可增加 Fusion-1。

### 6.4 替代轻量融合

若交叉注意力仍偏重，可用门控 FiLM：

- 将 \(H_{ctx}\) 池化为向量 \(h \in \mathbb{R}^{B \times d_h}\)。
- 经 MLP 生成逐通道缩放 \(\alpha\) 和偏移 \(\beta\)。
- \(F' = F \cdot (1+\alpha) + \beta\)。

默认推荐交叉注意力，FiLM 作为降级方案。

---

## 7. 输出头

### 7.1 策略头

- 输入：融合后的空间特征 \(F_{fused} \in \mathbb{R}^{B \times C \times 19 \times 19}\)。
- 结构：\(1\times1\) 卷积到 362 通道（361 落子 + pass），输出 logits。
- 输出：策略先验 \(P \in \mathbb{R}^{B \times 362}\)，经 softmax 归一化。
- 合法性掩码：在 MCTS 和训练损失中屏蔽非法着法。

### 7.2 价值头

- 输入：\(F_{fused}\) 经全局平均池化得到 \(v_{spatial} \in \mathbb{R}^{B \times C}\)，与全局标量特征 \(g\) 拼接。
- 结构：两层 MLP，隐藏维度 256，输出：
  - 胜率标量 \(V \in [0,1]\)（sigmoid），或
  - 盘面差分布（可选，增加少量开销）。
- 默认输出胜率标量，保持低开销。

### 7.3 可选辅助头

- Ownership 头：\(1\times1\) 卷积到 1 通道，预测终局盘面归属。默认不启用；若训练数据含 ownership 标签且推理预算允许，可启用。

---

## 8. MCTS 集成

### 8.1 基本参数

- 模拟次数 \(N_{sim}\)：默认 128；低开销模式 64；高质量模式 200。
- \(c_{puct}\)：默认 1.5–2.5，可按验证调整。
- 先验温度/根节点噪声：训练自对弈时使用；推理对局可关闭。
- 树复用：对局中保留搜索树，对手落子后若命中已有子树，则复用。

### 8.2 网络调用

- 每次 MCTS 扩展叶子节点时，调用一次网络前向，得到 \(P\) 和 \(V\)。
- 历史 Encoder 的输入随当前局面变化；每个叶子节点对应不同历史序列，需按叶子局面构造历史。
- 为控制开销，历史长度 \(T=8\)，Encoder 层数 2；融合模块只在少数层执行。

### 8.3 落子选择

- 训练自对弈：按访问次数分布采样，带温度。
- 推理对局：默认选访问次数最多的着法；可选按访问分布采样。

## 9. 训练方案

### 9.1 数据来源

优先使用 KataGo 自对弈数据或公开训练数据，包含：

- 局面 \(s\)
- 策略目标 \(\pi\)：MCTS 访问分布（软标签）
- 价值目标 \(z\)：终局结果或 KataGo 价值估计
- 可选 ownership 目标

训练流程以监督/蒸馏为主，自对弈微调为可选阶段。

### 9.2 损失函数

\[
\mathcal{L} = \lambda_p \mathcal{L}_{policy} + \lambda_v \mathcal{L}_{value} + \lambda_{aux}\mathcal{L}_{aux}
\]

- 策略损失：\(\mathcal{L}_{policy} = -\sum_a \pi(a) \log P(a)\)，或 KL 散度。
- 价值损失：\(\mathcal{L}_{value} = (V - z)^2\)，或交叉熵（若使用分布）。
- 辅助损失：可选，默认 \(\lambda_{aux}=0\)。
- 默认权重：\(\lambda_p=1.0\)，\(\lambda_v=1.0\)。

### 9.3 数据增强

- 棋盘旋转与翻转（8 种对称变换），同时变换策略目标。
- 颜色翻转（黑白互换），同时变换棋子平面、轮次和策略目标。
- 注意：中国规则贴目不对称时，颜色翻转需相应调整贴目符号或禁用该增强。

### 9.4 训练阶段建议

1. 阶段 A：蒸馏预训练
   - 使用 KataGo 数据，训练策略头和价值头。
   - 历史 Encoder 和融合模块同步训练。
   - 损失以策略 KL + 价值 MSE 为主。
2. 阶段 B：小规模自对弈微调（可选）
   - 若算力允许，用当前模型 + MCTS 自对弈生成数据，继续训练。
   - 若算力受限，可跳过，仅使用蒸馏模型。

### 9.5 课程与超参数

- 初始学习率：\(1e-3\)（AdamW），按验证集调整。
- Batch size：按显存选择，默认 256–512。
- 训练轮数：由验证集早停决定。
- 混合精度：启用 AMP。
- 梯度裁剪：默认 1.0。

## 10. 推理流程

```
输入当前局面 s，历史 H
1. 构造 F_board, H_tok, g
2. CNN 主干前向：
   for block in blocks:
        F = block(F)
        if block 是融合点:
            H_ctx = HistoryEncoder(H_tok)   # 可复用/缓存
            F = CrossAttentionFusion(F, H_ctx)
3. 策略头输出 P，价值头输出 V
4. MCTS 使用 P, V 进行 N_sim 次模拟
5. 选择落子 a
6. 更新历史 H ← H ∪ {(s, a)}
```

延迟控制开关：

- `fusion_points`：默认 2，可降为 1。
- `history_len T`：默认 8，可降为 4。
- `history_encoder_layers`：默认 2，可降为 1。
- `query_patch`：默认 2×2 下采样；若延迟允许可改为 1×1（361 token）。
- `N_sim`：默认 128，可降为 64。

## 12. 消融与验证计划

### 12.1 消融维度

1. 融合方式：
   - 无融合（纯 CNN 基线）
   - 晚期拼接
   - 交叉注意力融合（默认）
   - FiLM 融合
2. 融合点数：1 vs 2 vs 3。
3. 历史长度：4 vs 8 vs 16。
4. 历史 Encoder 层数：1 vs 2 vs 4。
5. Query 粒度：2×2 patch vs 1×1（361 token）。
6. 历史编码方案：线性投影 vs 微型 CNN。

### 12.2 评估指标

- 策略准确率：对 KataGo 访问分布的 top-1/top-3 一致率、KL 散度。
- 价值误差：MSE 或胜率校准误差。
- 延迟归一化胜率：在固定每步时间预算下，与基线模型对弈胜率。
- 局部战术测试集：紧气、征子、打劫、局部死活的专项准确率。
- MCTS 模拟次数曲线：固定网络下，胜率随 \(N_{sim}\) 的变化，用于确定收益递减点。

### 12.3 验证流程

1. 小规模代理任务：用少量数据训练多个配置，比较验证集策略/价值指标和推理延迟。
2. 选定 2–3 个候选配置，训练完整模型。
3. 用固定 MCTS 预算进行对弈评估，比较延迟归一化胜率。
4. 根据结果调整融合点、历史长度和 MCTS 模拟次数。

## 13. 工程实现要点

- 框架：PyTorch 或 JAX，按团队熟悉度选择。
- 混合精度：启用 AMP，注意 LayerNorm 和 softmax 的数值稳定性。
- 历史 Encoder 复用：同一局面在 MCTS 多个叶子中可能重复出现历史序列，可按局面哈希缓存 \(H_{ctx}\)；简单实现可先不做。
- 合法性掩码：策略 softmax 前屏蔽非法着法；训练损失中忽略非法着法。
- 对称增强：在数据加载器中实现 8 种对称变换，确保策略目标同步变换。
- 检查点：保存模型参数、优化器状态、历史长度和融合配置，保证推理配置与训练一致。
- 推理引擎：网络前向与 MCTS 解耦，MCTS 以批处理方式调用网络；支持单局面和多局面批推理。

## 14. 风险与回退方案

| 风险 | 回退方案 |
|---|---|
| 交叉注意力延迟过高 | 减少融合点至 1；改用 FiLM；降低 Query token 数 |
| 历史 Encoder 训练不稳定 | 减少层数至 1；增大 LayerNorm eps；降低学习率 |
| 历史信息未被有效利用 | 检查历史 token 构造；增加历史长度；调整融合位置 |
| 局部战术精度不足 | 增加 CNN 通道或残差块；提高输入特征分辨率；检查 Query 下采样是否过粗 |
| 训练数据不足 | 优先使用 KataGo 蒸馏数据；跳过自对弈微调 |
| 推理配置与训练不一致 | 固化配置表；推理前校验历史长度、融合点数、输入通道 |

## 15. 附录：关键张量形状与伪代码

### 15.1 张量形状

| 名称 | 形状 |
|---|---|
| \(F_{board}\) | \([B, C_{in}, 19, 19]\) |
| CNN 特征 \(F\) | \([B, C, 19, 19]\) |
| 历史 token \(H_{tok}\) | \([B, T, d_h]\) |
| 历史上下文 \(H_{ctx}\) | \([B, T, d_h]\) |
| Query \(Q\) | \([B, 100, d_h]\)（2×2 下采样） |
| 策略 logits | \([B, 362]\) |
| 价值 \(V\) | \([B, 1]\) |

### 15.2 融合模块伪代码

```python
def fusion_block(F, H_ctx, d_h, C):
    # F: [B, C, 19, 19]
    # H_ctx: [B, T, d_h]
    Q_map = conv1x1(F, C -> d_h)          # [B, d_h, 19, 19]
    Q = patchify_2x2(Q_map)                # [B, 100, d_h]
    K = linear(H_ctx)                      # [B, T, d_h]
    V = linear(H_ctx)                      # [B, T, d_h]
    A = cross_attention(Q, K, V)           # [B, 100, d_h]
    A_map = unpatchify_2x2(A)              # [B, d_h, 19, 19] 或上采样
    delta = conv1x1(A_map, d_h -> C)       # [B, C, 19, 19]
    gamma = learnable_gate()               # 标量或逐通道，初始 0.1
    return F + gamma * delta
```

### 15.3 训练伪代码

```python
for batch in dataloader:
    F_board, H_tok, g, pi_target, z_target = batch
    F = cnn_stem(F_board)
    H_ctx = history_encoder(H_tok)
    for i, block in enumerate(cnn_blocks):
        F = block(F)
        if i in fusion_points:
            F = fusion_block(F, H_ctx, d_h, C)
    P = policy_head(F)
    V = value_head(F, g)
    loss = policy_loss(P, pi_target) + value_loss(V, z_target)
    loss.backward()
    optimizer.step()
```
